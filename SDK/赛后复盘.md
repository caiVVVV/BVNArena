# 赛后复盘

打开竞技场的「回放」页，选中一场比赛，点击「赛后复盘」。原画面播放器也有同名按钮。报告会列出双方阵容、每个小回合的上场角色、掉血、回血、确认由本方造成的对手掉血，以及能核实的击倒来源和招式记录。

报告保存为 `.bvnreport.json`，文件名与同场 `.bvnreplay` 对应。新比赛结算或写入中断状态后会尝试自动生成报告。打开旧录像的复盘时，竞技场可以补生成报告。窗口底部可以复制完整路径，将 JSON 文件交给训练 AI。只有 `.bvndemo` 的情况下，可将同场的 JSON 报告放在它旁边后打开。

## JSON 字段

报告使用 UTF-8 编码，`format` 为 `bvn-arena-report/1`。

| 字段 | 内容 |
| --- | --- |
| `attempt` | 对局和系列赛 ID、地图、赛制、赛前比分和裁判结算。`status` 可为 `finished`、`forfeit`、`interrupted` 或 `unknown`。`seriesRound` 是系列赛局次。`mode` 包括正式比赛 `ranked`、玩家对 AI `human` 和人机练习 `cpu`。 |
| `players` | 按本局 P1、P2 顺序列出报名身份 `side`、阵容 `roster`、援助 `assist` 和己方统计 `damage`。`kind` 为 `entrant`、`human`、`cpu` 或未知时的 `null`。 |
| `rounds` | 每个游戏小回合中双方实际观察到的上场角色、统计和已确认来源及招式的累计掉血。`startTick`、`endTick` 是该回合首末记录的逻辑帧。 |
| `events` | 按逻辑帧排列的掉血 `damage`、回血 `heal`、出招 `attack` 和击倒或血量归零 `ko`。具体类别取决于档案里的证据。 |
| `coverage` | 逻辑帧、原生血量变化、通过相邻血量补记的变化、原生出招和原生击倒各有多少条。 |

`hpLost` 只累计实际扣掉的血量，剩余 5 点血时被打至 0 只计 5 点。`hpHealed` 单独累计。相邻观测须属于同一小回合的同一场上角色才会用于推算血量变化。

`hpDealtConfirmed` 累计有明确来源座位、由本方造成的对手掉血。`hpLostToOpponentConfirmed`、`hpLostToSelfConfirmed` 和 `hpLostUnattributed` 从受击方视角统计。`source` 为空或 `confirmed` 为 `false` 时，来源待确认。`evidence` 为 `hp_observation` 时，`amount` 是相邻血量之间未经原生事件解释的差额。缺失的事件可能发生在两次观测之间。

`rounds[].moves` 按小回合、来源、招式和目标累计，`hits` 是这些条件下的确认掉血记录条数，`hpLost` 是它们实际扣掉的血量。有时统计会涵盖同一招的多次使用。出招事件记录游戏观察到的动作。判断这次动作是否打中，需要对应的伤害证据。

旧回放可能仅记录血量快照，换人前也可能缺少血量归零的观测。复盘时先看裁判结算，再结合已记录的小回合和伤害事件分析。可按 `tick` 查看原画面或定位相关对局记录。
