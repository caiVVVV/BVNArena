# 选手 JSONL 协议 1

每条消息是 UTF-8 编码的一个 JSON 对象，以换行结束。每条回复最多 64 KiB。裁判为每次请求发放新的 `requestId`，必须原样回传。输出多余调试文字、无效 JSON 或超长行会终止该选手的协议会话。每次回复后立即刷新标准输出。

## 选角

裁判分别向两席发送下列结构。示例中的 ID、人数及数值仅用于说明；实际取值以运行时名单为准。

```json
{"type":"draft","requestId":"d7e3","matchId":"a986","seat":1,"map":"dangai","score":[1,0],"teams":[{"name":"绯刃","color":"#D74737"},{"name":"苍潮","color":"#2875CA"}],"fighters":["ichigo","lee","itachi","gaara"],"assists":["a1","a2"],"maps":["dangai"],"teamSize":3}
```

`seat` 为 1 或 2。`teams` 和 `score` 依次对应本局 P1、P2，比分是本局开始前的系列赛积分。`roster` 的长度须等于 `teamSize`；角色必须来自 `fighters` 且本队内不重复。`assist` 从 `assists` 选一个。回复示例

```json
{"type":"pick","requestId":"d7e3","roster":["lee","ichigo","gaara"],"assist":"a1"}
```

## 战斗

裁判发出原版游戏的一次公开观测。`tick` 是此局的游戏帧号，可能跳号。请以真实观测和帧号更新本地状态，避免假设每次调用间隔固定。

```json
{"type":"frame","matchId":"a986","tick":102,"seat":2,"requestId":"b5ae","players":[{"id":"lee","x":118,"y":0,"hp":650,"hpMax":700},{"id":"itachi","x":246,"y":0,"hp":550,"hpMax":680}]}
```

`players[seat-1]` 是自己，`players[2-seat]` 是对手。角色信息可包括 `id`、`name`、`x`、`y`、`hp`、`hpMax`、`energy`、`qi`、`facing`、`state` 和 `air`。原版角色没有公开某个字段时，应能处理缺失或空值。数值的范围、动作状态和能量成本由角色和游戏决定。请兼容额外字段。

双方阵容锁定后，新版裁判在 `frame` 中提供 `lineups` 和 `opponent`。前者按 P1、P2 排列，成员的 `roster` 与 `rosterNames` 按出场顺序提供游戏 ID 和中文名，`assist` 与 `assistName` 提供援助的 ID 和中文名。`opponent` 提供同样的对手阵容，并用 `activeId`、`activeName` 标出当前场上角色。选角请求阶段双方阵容仍然保密。兼容早期裁判时，这些字段可能缺失。

回复应回传当前的 `requestId` 和整数 `tick`。裁判丢弃旧请求、错误帧号和截止后才收到的回复。

```json
{"type":"action","requestId":"b5ae","tick":102,"buttons":["forward","attack"]}
```

### 按键与组合

每次回复的 `buttons` 都是当前按住的完整列表，方向键和招式键可同一条发送。省略某键就会松开该键，`[]` 松开全部。需要重新点按时，先在至少一次回复中省略该键，再将它加回。长按蓄力时连续保留相应按键。一个列表内，`left/right`、`forward/back`、`up/down` 各只能取一边，绝对与相对水平方向也不可混用。重复键名会去重。

| 操作 | `buttons` 示例 | 游戏用法与条件 |
| --- | --- | --- |
| 水平移动 | `["left"]`、`["right"]`、`["forward"]`、`["back"]` | 前两者是屏幕方向，后两者是朝向／背离对手。追击、拉开距离或守版边时可据位置选用。 |
| 防御与上方向 | `["down"]`、`["up"]` | 地面可防御时按住下防御。`up` 为上方向，可与招式键组合。 |
| 普攻与组合攻击 | `["attack"]`、`["up","attack"]`、`["down","attack"]` | 对应常见攻略的 J、WJ、SJ。普攻连段须在有效窗口内重新按键。近身横向组合是否为投技由角色与规则决定。 |
| 技能与组合技能 | `["skill"]`、`["up","skill"]`、`["down","skill"]` | 对应 U、WU、SU。作用、蓄力、派生和资源因角色与形态而异。 |
| 冲刺、瞬步与幽步 | `["dash"]`、`["forward","dash"]`、`["up","dash"]`、`["down","dash"]` | `dash` 对应 L。L 的基础用途为冲刺或瞬步。WL、SL 属于幽步或快速位移动作，受角色、状态与规则限制，位移和是否穿过平台要用本配置验证。 |
| 跳跃与空中出招 | `["jump"]`、`["forward","jump"]`、空中 `["attack"]`／`["skill"]`／`["super"]` | `jump` 对应 K。空中可用时重新点按 K 可尝试二段跳。攻略的 KJ、KU、KI 通常指起跳后在空中出招，何时按招式键取决于角色与连段。 |
| 从较高平台下落 | `["down","jump"]` | 对应 SK。站在可向下穿过的台阶且能行动时，按住下方向并点按跳跃。结合随后 `air` 和 `y`（向下为增大）确认离开台阶。 |
| 必杀、方向必杀、超必杀 | `["super"]`、`["up","super"]`、`["down","super"]` | 对应 I、WI、SI。受角色、气量和动作状态限制。具体扣气、扣血或返还见对应角色，出招结果以随后观测确认。 |
| 辅助与方向辅助 | `["assist"]`、`["up","assist"]`、`["down","assist"]` | 对应 O、WO、SO。需要满足辅助能量和可召唤状态，部分辅助支持方向变体或二次召唤。 |
| 松开全部按键 | `[]` | 在需要空输入或为下一次点按做准备时发送。 |

验证任何动作时，比较出招前后的自身与对手位置、`state`、`air`、`hp` 和可用资源字段。确认候选按键已松开、角色满足出招条件，并考虑两次观测间可能经过多个游戏帧。角色和辅助的已知效果、触发条件与资源代价见 [角色与辅助图鉴.html](角色与辅助图鉴.html)。

## 进程生命周期

每个进程只打当前一局。首次消息是 `draft`，之后是零到多条 `frame`。比赛结果和录制由主持人端管理。读取到标准输入 EOF 后应退出。裁判也可在本局结束或被停止时直接结束进程。开发时若需要输出诊断，请写入自己的调试文件，比赛裁判会丢弃标准错误。
